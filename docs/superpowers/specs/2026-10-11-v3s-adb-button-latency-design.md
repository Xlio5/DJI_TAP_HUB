# V3S ADB 按键低延迟设计

## 目标

在不提高摇杆常态发送频率、不丢失按下/放开边沿的前提下，将 V3S ADB 模式下按键到 Android UI 的典型延迟从 30-50ms 降至 8-20ms。

## 根因

当前链路串联了三个独立的 20ms 周期：V3S ADB 融合发布、`dji_rc` RCMSG 主循环、Android UI pump。网络实测年龄约 5ms，但周期相位叠加会额外引入 0-60ms，Compose 绘制还可能再等待一个显示帧。

## 设计

### V3S

- 保留 20ms 超时发布，摇杆轴继续稳定输出约 50Hz。
- getevent 或 40007 捕获到有效事件后，通过独立条件变量唤醒 ADB 融合线程。
- 融合线程发现按键边沿后更新 `g_adb_rc`，再唤醒 `dji_rc` 主循环立即发送 RCMSG。
- 主循环仍以 20ms 为最大等待时间，配置热加载、状态文件和遥测逻辑保持原行为。
- 条件变量只负责降低等待时间；有界边沿 FIFO 继续负责保存 DOWN/UP 顺序。

### Android

- RCMSG 接收线程继续把最新数据写入 `RcMsgUiPump`，供摇杆轴按 20ms 聚合刷新。
- `RcMsgUiPump` 在按键掩码变化时返回该边沿；接收线程将其写入容量 32 的有界 `Channel`。
- 主线程协程立即消费按键 Channel 并调用现有 `applyRcData`；周期 pump 保留，重复状态由现有相等判断跳过。
- Channel 满时丢弃最旧边沿，与 V3S FIFO 的现有过载策略一致，避免阻塞网络线程。

## 正确性约束

- DOWN 和 UP 必须按接收顺序显示。
- 静止或仅摇杆变化时不得触发额外 Compose 状态更新。
- V3S 无事件时 RCMSG 仍维持约 50Hz。
- 退出或重启时条件变量必须唤醒，线程不能因等待而阻塞退出。

## 验证

- Android 单元测试验证首帧不算边沿、DOWN/UP 均被返回且顺序不变。
- C++ 单元测试验证事件代次在变化时触发、无变化时超时、停止时可唤醒。
- 完整构建 Android APK 与 V3S rootfs/SPI，并部署后读取版本、输入模式和 RCMSG 速率。
- 实机连续按键，确认状态无锁存、无丢边沿，RCMSG 常态频率仍约 50Hz。
