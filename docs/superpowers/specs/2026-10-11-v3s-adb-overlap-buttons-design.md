# V3S ADB 重叠按键严格归属设计

## 背景

V3S ADB 模式同时读取 Android `getevent` 和本机 TCP 40007。`REC`、`SHOT`
在两路中均存在，当前 OR 融合会在两路边沿时间不同的情况下产生重复触发。

## 决策

- V3S ADB 模式下，`REC`、`SHOT` 严格以 `getevent` 为唯一来源。
- 40007 中的 `REC`、`SHOT` 仍允许被协议解码，但在进入融合状态前清零。
- 40007 的按键边沿检测基于清理后的状态，因此这两个字段不会触发直接 RCMSG。
- 40007 继续提供 STOP、模式、拨轮、C1/C2/C3 等非重叠状态。
- `getevent` 未建立或断开时不回退 40007 的 `REC`、`SHOT`，避免输入源切换制造假边沿。

## 数据流

1. 40007 数据包完成 CRC 校验和解码。
2. 合并 40007 分包状态。
3. 清除 40007 状态中的 `rec`、`shot`。
4. 对清理后的 40007 状态执行边沿检测。
5. 融合时 CH1-CH6 和 `REC`、`SHOT` 取 `getevent`，其余字段取 40007。
6. 40007 非重叠按键继续即时发送；周期 RCMSG 保持约 50Hz。

## 验证

- 单元测试证明 40007 的 REC/SHOT 无法改变融合输出。
- 单元测试证明 getevent 的 REC/SHOT 可以正常按下和释放。
- 单元测试证明清除重叠字段后，40007 REC/SHOT 不构成按键边沿，而 STOP 等仍构成边沿。
- 完整 Ubuntu 测试、固件构建、部署和设备状态读回通过。
