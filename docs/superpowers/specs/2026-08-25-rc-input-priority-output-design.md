# 2026-08-25 RC 输入优先级输出设计

## 目标

`dji_rc` 支持两路 DJI RC 输入：

- `ttyS1 @921600`：高优先级 RC 输入。
- `ttyS2 @115200`：低优先级兜底 RC 输入。

输出口的 SBUS/CRSF 协议和输出波特率仍由现有 Web/App 配置决定；本设计只改变“哪一路输入状态驱动输出”和“输出节拍来自哪里”。

## 行为

1. 921600 路在最近 `50ms` 内有有效 RC 包时，SBUS/CRSF 按 921600 路有效 RC 包到达节奏输出。
2. 921600 路超过 `50ms` 没有有效 RC 包时，如果 115200 路在 `500ms` stale 窗口内有效，则 SBUS/CRSF 按 115200 路有效 RC 包到达节奏输出。
3. 两路都失效时不输出新的通道帧，状态文件进入 no RC 或保持当前无有效源状态。
4. 921600 恢复后，下一个 921600 有效 RC 包立即重新抢占输出源。
5. 921600 活跃期间，115200 路即使也收到有效 RC 包，也只更新自身状态计数，不触发串口输出，避免双路叠加导致输出频率翻倍。

## 实现边界

- 新增 `rc_source_select` 纯选择模块，便于主机单元测试。
- `rx_thread` 每解析到有效 RC 包后触发一次源选择和输出。
- 主循环继续负责 `/tmp/rc_state.json`、`/var/log/rc_state.json`、rcmsg UDP 上报、配置热加载和遥测上报。
- 主循环不再直接调用 `out_send()`，避免事件驱动输出和固定周期输出重复。
- 状态 JSON 增加 `active_src` 字段，值为 `921600`、`115200` 或 `none`。

## 验证

- 单元测试覆盖 921600 50ms 内优先、921600 超时后 115200 接管、921600 无数据时 115200 工作、两路都失效时不选源。
- native 构建验证 `rc_source_select_test`。
- 交叉编译验证 `dji_rc` 可链接 `rc_source_select.cpp`。
- rootfs 解包读回验证 `dji_rc` 包含 `active_src` 和 `921600` 字符串。
